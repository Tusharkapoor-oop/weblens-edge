- It does not browse on behalf of a user or model: no clicking, form filling, logins, session or cookie persistence for a user, purchases, screenshots for agents, or autonomous multi-step task execution against websites.

- It is not an LLM and not an answer engine by default. The default mode returns evidence; any built-in synthesis is an optional plug-in.
- Do not build features, benchmarks or marketing claims whose purpose is to compete with AI browsers or browser-agent products (Playwright MCP, Claude in Chrome, and similar). Such tools may appear in comparisons only to show where JavaScript rendering is needed.

MISSION
Run an unattended, never-idle loop: find errors, fix them, find what is missing, add it, test every feature, improve it, penetration-test it, repeat. Use a team of sub-agents with separated roles. The owner has plenty of model tokens, so thoroughness is not limited by tokens; it is limited by evidence quality, fresh held-out data, Tavily credits, search-engine politeness and safety. Therefore the loop keeps running through a ladder of ever-harder work instead of stopping after a quiet cycle, but it never fakes progress: a cycle that keeps nothing is a valid result, and every number still comes from the ledger.

PART A: OPERATING MODEL

A1. State and resume (the loop must survive session ends, crashes and context limits)
- Keep `evidence/loop/STATE.json` (written by script after every phase): cycle number, phase, next step, pending tasks, open defects, rejected ideas, backlog, held-out slices used and how many times each was looked at, credit plan and spend, ledger head hash, git commit, owner notes read-at time.

A2. Restart driver
Create `tools/loop_driver.ps1` and `tools/loop_driver.sh`. A3. Stop rules (there is no wall-clock or fixed cycle-count stop)

If live Tavily credits are exhausted the loop continues with offline and local work and marks Tavily comparisons NOT RUN.

A4. Heartbeat
After every cycle: generate `reports/loop/cycle-<n>.md` and `reports/loop/STATUS.md` by script (cycle number, kept and rejected changes, top five remaining losses, security status, credits spent and left, next planned phase, ledger head hash), push a checkpoint to the private remote, and print one line with the cycle number, counts and ledger head hash. - Local limits: cap concurrent sub-agents (default 4), CPU and RAM, disk growth (cache, fuzz corpora, raw logs), and kill orphan browsers and containers at the end of every cycle.
- Attack and fuzz work only inside the isolated environment with canary secrets, never against third parties.
